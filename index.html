PART 01 · VALUE & MODE

先看结论：AI 接走了哪些环节

不按版本讲功能，先讲清三件事：原来工作怎么做、AI 接手哪一段、人还需要判断什么。第二部分每项能力的模式对比与能力详解，都围绕这条主线展开。

01

一页看懂：AI 替我们接走了什么

AI 不是多一个工具，而是接进现有工作流：把重复、可规则化的环节拿走，把需要经验判断的环节留给业务人员。

ONE PAGE SUMMARY 搬数据、套公式、做初稿交给 AI；
定口径、判异常、做决策留给人。

判断一个 AI 功能有没有价值，不看它会不会聊天，看它能不能把原流程里的某一段真正接走，并且交付一个可以直接用的文件。

两份清单放一起，差在哪一目了然

cost-analysis-v5 · 模拟清单 vs 转固清单 七维对比
干嘛的
把两份造价清单放一起逐项对：工程量差多少、单价差多少、合价差多少、消耗量差多少，还能标出「只在一边出现的新增/取消项」。要跟目标成本一起看也可以叠进去。最后给你一张 Excel 对比表（每个业态一个 sheet）+ 一份文字分析报告，开会报审直接用。
什么时候用
拿到转固清单，想知道「转固和合同比，变化在哪、变化多大」的时候。
照抄这句
这两份清单，帮我对比一下转固和合同的差异，出一张对比表和一份报告。
它中途会问你什么（心里先有数）▾
第 1 问
检查你给的清单是不是标准清单。给错了它会直接说「这是审核清单对比表，请换导出的标准清单」——它宁愿停下来问你，也不会硬算出一堆错数。
第 2 问
报它认出来的业态和楼栋：「识别到 7 个业态、小高层 9 栋…」，你扫一眼，不对当场纠正。
第 3 问
可能要你补面积。你有面积表就发过去；没有它会给你一份模板，你只填「地上面积、地下面积、基底面积」几列再发回来，实际建筑面积留空也行，它自己补。
三个最容易被坑的点（记住这些少返工）▾
给错文件，它不会硬算：如果给的是《审核清单对比表》（「小高层-地上」「汇总表」这种招标/转固/一审并排的表），工具会直接停下来告诉你「这不是标准清单，请换导出的标准清单」——不会闷头算出一堆错数。你没做错什么，换成工具导出的标准清单（sheet 名以 4 开头，如「4.1.1. 小高层」）重发就行。
表里的「—」不是 0。「—」意思是这边算不出来（比如没面积），上会前别把它当 0 元念出去。
某业态只在一边出现，先对口径再下结论。可能两份文件不是同一版项目，让 AI 在报告里标出来，别当成 0 处理。
结果出来后，还能接着这么问▾
转固比合同少了多少？哪个业态变化最大？
把地下非人防车库的差异按科目列出来。
有哪些是转固新增的项？金额多少？
能不能把我的目标成本也叠进去一起看？

工程造价 · 招标排期

模板加排程，招标计划一次生成

bid-planner · 单组团 / 多组团合并 / 招标方式判断
干嘛的
读取基础合约规划模板和智计划排程，按业态筛选品类、估算金额、判断招标方式，再按合理招标期量倒推入围与合同需求时间；多组团可按时间邻近关系合并，最终输出单组团或多组团招标规划 Excel。
什么时候用
新项目编制招标规划、调整招标方式参数后重算、多组团合并排期，或需要解释某品类的招标时间链如何倒推时。
照抄这句
根据这份基础合约规划模板和智计划排程，生成这个项目的招标规划 Excel；排程缺节点的先列出来，不要直接猜。
它按什么逻辑排招标计划▾
判断项核心规则会落到什么结果
招标方式垄断品类优先直接委托；集采品类走集采转签；其余按品类类型与预估金额阈值判断邀请招标、简易招标或比价每个品类得到明确招标方式，并随合并金额重新判断
时间链倒推定标对应工程开始节点；入围 = 定标 − 合理招标期量；合同需求 = 入围 − 3 天；需要图纸的再往前倒推形成可执行的入围、合同需求、图纸提交与定标日期
多组团合并同品类、同智计划节点，且组团时间相邻不超过阈值时合并；合并后金额求和、时间取最早减少零散招标批次，同时保留各组团明细
最容易错的三个点▾
排程缺节点：部分节点可由引擎推导，但推不出的会带缺失提示。涉及关键时间链时，先补齐智计划节点再生成。
.xls 打不开：有些导出件实际是 HTML 模拟表格，引擎会尝试识别并兼容解析；仍然失败时改为提供节点日期清单。
招标方式不对：先核对地区垄断品类、集采目录和金额口径，再检查业态与面积是否填对。

把多组团合并的相邻天数阈值调整到 45 天，重新生成一版。

能力详解 · 四：AB类协议生成

原名 ab-contract-generator。场景：工抵 / 抵扣房款业务定稿时，要按台账一次出齐「抵扣房款协议 + AB 确认书 + 委托咨询服务合同」，每份都要换主体、换金额、换房源，手工做一套要两三天。

你上传

一份标准台账 Excel（表头第 3 行、数据第 4 行起填）：抵扣合同、购房人、房源、咨询服务信息与协议模板；另确认服务合同税率 3% 或 6%。

你拿到

抵扣房款协议、AB 确认书、委托咨询服务合同三份 Word + AB_agreements.zip，附协议编号 / 售房单位 / 分供方 / 购房人 / 税费摘要。

工程造价 · 协议套件

一份台账，三份协议一次出齐

ab-contract-generator · 2 方 / 3 方 / 4 方个人 / 4 方公司自动判定
干嘛的
读一份抵扣 / 抵房业务台账，按业务形态自动判定协议主体（2 方 / 3 方 / 4 方个人 / 4 方公司），补齐企业信息，套 Word 模板一次生成抵扣房款协议、AB 确认书、委托咨询服务合同三份文件，并打包成一个 zip。签署栏的甲 / 乙 / 丙 / 丁名称、抵扣明细表序号与附表合并、咨询费口径都按规则自动处理。
什么时候用
工抵 / 抵扣房款业务要出协议套件；一批台账要批量生成；或者需要复现、核对其他系统已生成协议的内容时。
照抄这句
这套 AB 类协议帮我生成；信息缺的先列出来，不要直接猜。
它按什么规则判定协议主体▾
台账里的情形判定结果签署栏
购房信息为空，且欠款单位都等于售房单位2 方协议：售房单位 + 分供方甲 / 乙
购房人是个人4 方个人协议甲 / 乙 / 丙 / 丁
购房人是公司4 方公司协议甲 / 乙 / 丙 / 丁
其他情形3 方协议甲 / 乙 / 丙
咨询费也按规则自动算：房源总价低于 30 万按 500 元/套，30 万以上按总价 0.1%，税率用你确认的 3% 或 6%。多个欠款单位时签署栏会自动编号（欠款单位 1、2…），同一合同多行在附表里纵向合并。
三个最容易被坑的点▾
台账格式别自己改造。表头必须落在第 3 行、数据从第 4 行开始，合并单元格和表头行不要挪位置。格式太乱解析会失败，建议直接用标准模板重填。
协议里企业信息是空的？企业地址、法定代表人、统一社会信用代码来自数据库与企信接口。离线或不在办公网时会缺失，其余内容正常——要么补齐这几项，要么连上办公网重跑一次。
该出 2 方却出成 3 方。两方判定依赖数据库比对「欠款单位是否等于售房单位」，查不到会退化成 3 方。确认是甲乙两方场景时，直接告诉它「按两方协议生成」。
结果出来后，还能接着这么问▾
这份台账按 6% 的咨询服务税率重新生成一版。
这批台账一起生成，每个项目放进单独的文件夹。
把三份协议里的购房人、房源、抵扣金额列成一张核对表给我。
这次生成里哪些字段是缺的？列个清单，我先去补。

琐碎的表格、文档、PPT、PDF 活可以直接交给 AI。你只需要说明“这个文件帮我干嘛”，剩下的格式、计算与交付由对应技能处理；网页设计工程师负责把结果转成可视化看板。

Excel 专家 xlsx

网页自动化 web-access

干嘛的
让 AI 真的上网去办事，四类活都归它管：① 搜资料——查价格、新闻、政策，能给出来源出处；② 看网页——打开指定网址，把页面内容读给你 / 抽取出来；③ 抓平台——小红书 / 微博 / 公众号这些平台的内容；④ 进系统——操作需要登录的网站（比如进某个系统里取数据）。像一个坐在那台上电脑的真人助理。
